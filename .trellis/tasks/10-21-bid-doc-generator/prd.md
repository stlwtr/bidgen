# 投标文档生成助手 (bid-doc-generator)

## Goal

面向政府采购投标场景，提供一个通用命令行助手：输入**招标文件 PDF** 与**供应商信息配置**，输出一份结构化、格式规范的**投标文件 Word 初稿**。

助手职责：把招标文件里的"投标文件格式"章节（目录 + 各格式模板）抽取出来重建为投标文件骨架；从招标文件采集采购人 / 采购代理机构 / 项目名称 / 项目编号等字段，自动填充固定格式的承诺函；从资格审查、评标办法章节提取资格项 / 符合性审查项 / 评分项，编入商务部分；技术偏离表按采购需求生成待填骨架。供应商自身信息与技术方案由配置文件提供或留空占位。

用户价值：把"人工从招标文件复制格式、逐个填写承诺函、调排版、设页眉页脚、排标题编号"的数小时工作，压缩为一条命令。

## Background

### 参考材料（仓库内唯一证据）

- `docs/2026年饶河县中考考点基本办学条件改善项目招标文件（[230524]YRZB[GK]2026000120260730001）.pdf`
  - 125 页，政府采购货物类公开招标文件，含图片/表格。
  - PDF 文本层存在**异体字形乱码**（康熙部首 / CJK Radicals Supplement），转 Word 后需修复。

| 第二章 投标人须知 | 前附表（保证金、有效期、评标办法等） |
| 第三章 采购需求 | 采购标的一览表、技术要求（技术偏离表来源） |

| 第六章 拟签订的合同文本 | 商务要求来源 |
| 第七章 投标文件格式与要求 | 封面 + 投标文件目录（16 项） + 格式一~格式十六 |

## Requirements

### 功能需求

- **R1 招标文件 PDF → Word**
  - 输入招标 PDF，输出招标文件 `.docx`。
  - 转出文本执行乱码修复（NFKC + 自定义映射）。
  - 保真度：文本、表格、段落顺序为主；**图片不保证保留**（实测 pdf2docx 与 LibreOffice 均未保留），复杂版式允许近似。
  - 已知代价：全量 125 页转换约 7 分钟。
- **R2 提取"投标文件格式"章节**
  - 定位第七章（或标题含"投标文件格式/投标文件格式与要求"的章节）。
  - 提取封面、投标文件目录（16 项）、格式一~格式十六的标题与正文模板文本。
- **R3 生成投标文件 Word 初稿（排版规范见 design §4.8）**
  - 封面：项目名称、项目编号、投标人、日期（采集或占位）；封面独立分节、无页眉页脚。
  - 目录：Word TOC 域，与各格式章节对应。
  - 章节骨架：标题层级正确，**一级标题自动编号**（中文数字，绑定 Heading 1）。
  - 页眉（项目名 / "投标文件"居中带下框线）+ 页脚（`第 X 页 共 Y 页`）。
  - 字体/段落：正文宋体小四、标题黑体、西文 Times New Roman、正文首行缩进 2 字符、行距 1.5；参数集中在 `StyleSpec`，可整体覆盖。
- **R4 字段采集**
  - 从招标文件规则提取：采购人（招标人）、采购代理机构、项目名称、项目编号。
  - 从供应商配置文件读取：公司名称、法定代表人、地址、电话、开户行、账号、授权代理人等。
- **R5 承诺函生成**
  - 对格式一（投标承诺书）、格式二（资格承诺函）、格式五（主要商务要求承诺书）等固定模板：使用招标文件原文模板 + 填充采集字段。
  - 未能提供的字段在 Word 中留 `______` 占位。
  - 模板正文空位按**通用规则**填充：采购人 / 采购代理机构名称、项目名称、项目编号、投标人名称（如 `按照已收到的 ____ 项目`、`（项目编号：____）`、`（投标人名称）`）；规则见 design §4.11。
- **R6 商务部分编制（资格申请、符合审查及评分项）**
  - 从第四章资格审查提取资格审查项。
  - 从第五章评标办法提取符合性审查表、综合评分表（技术评审 + 商务/价格评审）评分项。
  - 编入投标文件**各类证明材料**的"（一）招标文件要求提供的其他资料"对应类别，不再插入资格承诺函章节。
- **R10 各类证明材料输出格式（格式十六）**
  - `（一）招标文件要求提供的其他资料` 下按类别输出：`1.资格审查`（资格审查表）、`2.符合性审查`（符合性审查表）、`3.技术评审`（综合评分表·技术部分）、`4.商务评审`（综合评分表·商务/价格部分）；随后为 `（二）投标人认为需提供的其他资料`。
- **R8 中英标点规范化**
  - 中文语境里的半角标点 `, . : ; ! ?` 转为全角 `，。：；！？`；成对括号 / 引号在中文语境转全角。
  - **不改动**数字 / 字母 / 单位 / 型号 / 公式语境（金额 `3,649,020.00`、比例 `16:10`、`8dB(A)`、`(Cr)≤20`、`(1m,1w)`、纯英文句子）。规则见 design §4.9。
- **R9 元数据清理（默认开启，可关闭）**
  - 清除 Word 产物中的机器码与用户信息：`creator` / `lastModifiedBy` / `Company` / `Manager` / `Application` / `Template`、`<w:rsids>` 修订标识、`python-docx` 生成标记等。
  - CLI 提供 `--no-sanitize`（或 `bidgen sanitize <file.docx>`）；清理项见 design §4.10。

### 技术约束

- 语言：Python 3.9+ 命令行工具，运行环境为项目内 `.venv` 虚拟环境。
- 依赖：`PyMuPDF==1.24.14`（锁版本，兼容 pdf2docx）、`pdf2docx==0.5.8`、`python-docx`、`PyYAML`、`pytest`。
- 乱码修复：`unicodedata.normalize('NFKC', ...)` + CJK Radicals Supplement 自定义映射（如 `⻰→龙`、`⻚→页`、`⼾→户`）。
- 供应商信息输入：`supplier.yaml` / `supplier.json` 配置文件。
- 文本重建：PDF 提取按**物理行**给 `\n`，须做"行→段落"重建（去页眉页脚、编号起点识别、按列判定折行、跨页合并），避免每行成独立段落。
- 标点规范化：仅中文语境转换，数字 / 英文 / 公式语境保留（design §4.9）。
- 元数据清理：默认开启，清除 core/app 元数据与 `rsids`（design §4.10）。
- 不接入任何大模型 / 网络服务。

## Out of Scope

- 不接入 LLM，不生成语义性新内容（技术方案、评分项应答正文由供应商提供）。
- 不自动获取 / 填写供应商自身工商信息（由配置文件提供）。
- 不做电子签章、CA、上传采购平台等操作。
- 不计算评分、不判定资格通过与否。
- 不保证 PDF→Word 的像素级版式保真（图片、复杂排版允许近似）。
- 不生成"分项报价明细表"具体报价数据（格式四需按平台客户端填写）。

## Decisions

- D1 ✅ 技术栈：Python 3 CLI；PDF 读取 PyMuPDF，Word 生成/编辑 python-docx。
- D2 ✅ 内容生成：纯模板 + 规则提取，不接入 LLM。
- D3 ✅ 适用性：通用工具，自动定位任意政府采购货物类招标 PDF 的投标文件格式章节。
- D4 ✅ Word 生成：python-docx 从零构建，不以其转换出的招标 Word 为模板。
- D5 ✅ 供应商信息输入：配置文件（supplier.yaml / json）+ Word 留占位符。
